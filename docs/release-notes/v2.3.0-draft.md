## PackageReleaseNotes (Numerics.csproj, shown on NuGet.org)

```text
Version 2.3.0 fixes EmpiricalDistribution.Clone and its XML round trip, which lost the probability order and strictness of survival (descending) and tied-probability tables, and adds UnivariateDistributionBase.ParameterSetQuantiles, which evaluates the inverse CDF over many parameter sets of one family in a single call, bitwise identical to the per-row loop. Existing XML documents are unchanged. New members: a weighted UncertaintyAnalysisResults.ProcessMeanCurve; Statistics.ColumnPercentiles; GeneralizedPareto.MLE at a known location; a faster, bitwise identical GeneralizedExtremeValue.ParameterSetQuantiles; weighted PlottingPositions.Function; Statistics.WilsonScoreInterval; plotting-position (Weibull, type 6) Statistics.Percentile and its column form Statistics.ColumnPercentiles(..., PlottingPostionType); list forms of CCDF, LogPDF, LogCDF and LogCCDF on every univariate distribution, of Tools.Expm1 and Tools.Log1p, and of the bivariate copula PDF, CDF, ConditionalCDF and InverseConditionalCDF; Statistics.Percentile sorts faster with bitwise the same results; PlottingPositions.Alpha and the named weighted PlottingPositions.Function; IFixedParameterEstimation (GeneralizedPareto at a known location); Statistics.ColumnMeans; a Tools.Log1p accurate to the last unit at every argument. The release also introduces rmc-numerics, the Python wheel that ships this Numerics.dll with a CoreCLR loader and typed wrappers. See the v2.3.0 GitHub release notes for details.
```

## PR message

Title: `Prepare v2.3.0 release`

```markdown
## Summary

- Package, citation, CodeMeta and snapshot metadata set to 2.3.0 (`Numerics.csproj` Version,
  AssemblyVersion 2.3.0.0, PackageReleaseNotes; `CITATION.cff`; `codemeta.json`; `Snapshot.yml`
  advanced to the next patch).
- Fix: `EmpiricalDistribution.Clone` and `ToXElement`/`FromXElement` now preserve the X and
  probability sort orders, their strictness and the smart-search setting. Previously a survival
  table (strictly descending probabilities) or a tied-probability table cloned into an ascending,
  strictly increasing table that failed validation. `StrictXValues` and `StrictProbabilities`
  are written only when they depart from the default, so existing documents serialize
  byte-identically; new read-only properties `StrictXValues` and `StrictProbabilities`.
- API: `UnivariateDistributionBase.ParameterSetQuantiles(double[,] parameterSets,
  IList<double> probabilities, out bool[] valid)` returns the quantile matrix (one row per
  parameter set, one column per probability) and one validity flag per row. Rows are evaluated
  serially on one private clone (`ValidateParameters(row, false)` → `SetParameters(row)` →
  `InverseCDF`), so the result is bitwise identical to the per-row loop and independent of the
  machine; invalid rows are NaN, matching `BootstrapAnalysis.Quantiles`.
- API: `UncertaintyAnalysisResults.ProcessMeanCurve(UnivariateDistributionBase[] sampledDistributions,
  double[] probabilities, double[] weights, double minProbability, double maxProbability)`: the
  weighted mean (predictive) curve, sum(w F) / sum(w) on the unweighted method's quantile grid,
  fixed-chunk reduction and interpolation, for logic-tree branch weights. Equal weights take the
  unweighted computation, so the curve is bitwise identical to `ProcessMeanCurve` whatever the
  common value; zero weights drop a member. rmc-numerics `process_mean_curve(..., weights=)`. Tested by `Test_UncertaintyAnalysisWeightedMeanCurve`
  (uniform weights bitwise, integer weights bitwise equal to the replicated ensemble, the mixture
  quantile, zero weights, argument errors).
- API: `Statistics.ColumnPercentiles(double[,] data, IList<double> k)` and the overload with
  `out int[] excluded`: Type 7 percentiles of each column of a member-by-node matrix over its finite
  entries (NaN where a column has none), each column bitwise `Statistics.Percentile` of its finite
  entries; the columns run in parallel and independently, so the result does not depend on the
  thread count. rmc-numerics `statistics.column_percentiles`. Tested by `Test_ColumnPercentiles`
  (R type 7 values, bitwise against the per-column member with NaN, infinities and signed zeros,
  empty shapes, argument errors).
- API: `GeneralizedPareto.MLE(IList<double> sample, double location)`: maximum likelihood for the
  scale and shape with the location fixed (for example a peaks-over-threshold threshold), by the
  same Nelder-Mead search as `MLE(IList<double>)`, which fixes the location at the sample minimum
  and is unchanged; the start is the known-location linear-moment estimate, else the exponential
  estimate; a constant sample is refused. rmc-numerics `GeneralizedPareto.fit_known_location`. Tested in
  `Test_GeneralizedPareto` (an independent SciPy maximum, shift invariance, the Rao and Hamed
  threshold example, recovery on simulated bounded, exponential and heavy tails, argument errors).
- API: `UnivariateDistributionBase.ParameterSetQuantiles` is now `virtual`, and
  `GeneralizedExtremeValue` overrides it: log(-log p) is computed once per probability instead of
  once per row and the rows are not applied to the clone, through the private kernel that
  `GeneralizedExtremeValue.InverseCDF` now shares, so the values stay bitwise those of the per-row
  loop (about 2.5 to 3.5 times faster over 20,000 rows). Tested by `Test_ParameterSetQuantiles`
  (2,000 random rows with zero, signed-zero, tiny and extreme shapes and huge parameters,
  probabilities at and next to 0 and 1, invalid rows, the invalid-probability exception).
- API: `PlottingPositions.Function(IList<double> weights, double alpha)`: weighted plotting positions
  (c_i - alpha w_i) / (W + (1 - 2 alpha) W/n) with sequential cumulative and total weights, for
  importance-weighted samples, with alpha in [0, 0.5] so every position lies in [0, 1]; unit weights
  give bitwise `Function(int, double)`. rmc-numerics
  `statistics.weighted_plotting_positions`. Tested by `Test_PlottingPositions.Test_WeightedFunction`
  (unit weights bitwise for seven alphas and four sizes, hand-computed weighted cases, zero and
  scaled weights, argument errors).
- API: `Statistics.WilsonScoreInterval(double successes, double trials, double confidenceLevel)`: the
  Wilson score interval of a binomial proportion, clamped to [0, 1], in the documented operation
  order (z from `Normal(0, 1).InverseCDF(0.5 + level/2)`, z^2/n formed once); counts may be
  fractional. rmc-numerics `statistics.wilson_score_interval`. Tested by `Test_WilsonScoreInterval`
  (SciPy values, the operation order bitwise, argument errors).
- API: `Statistics.Percentile(IList<double> data, double k, PlottingPostionType type, bool dataIsSorted)`
  and its `IList<double> k` overload: percentiles interpolated between the order statistics at their
  plotting positions (rank h = (n + 1 - 2 alpha) k + alpha, or n k for Kaplan-Meier, held at the
  extremes), in the interpolation form of the Type 7 member; Weibull is Hyndman-Fan type 6, Hazen
  type 5 and Kaplan-Meier type 4. rmc-numerics `statistics.plotting_position_percentile`. Tested by
  `Test_PlottingPositionPercentile` (R types 6, 5 and 4, each order statistic at its position for
  every formula, array and sorted overloads bitwise, argument errors).
- API: `UnivariateDistributionBase.CCDF(IList<double>)`, `LogPDF(IList<double>)`, `LogCDF(IList<double>)`
  and `LogCCDF(IList<double>)`: the list forms beside `PDF`, `CDF` and `InverseCDF(IList<double>)`, each
  value bitwise the scalar member, so a caller crossing from Python evaluates an array in one call
  (10,000 survival probabilities: 14-21 ms element by element, 0.3 ms). Tested by
  `Test_UnivariateListOverloads` (every family the factory creates, bitwise against the scalar members
  over the supports, both zeros, the infinities and NaN; SciPy `sf`, `logsf`, `logcdf` and `logpdf`
  values; null and empty lists; invalid parameters).
- API: `Tools.Expm1(IList<double>)` and `Tools.Log1p(IList<double>)`: list forms, each value bitwise the
  scalar member. Tested by `Test_ToolsListOverloads` (bitwise at and around the 1E-4 switch and the
  special values; NumPy `expm1` and `log1p` values; null and empty lists).
- API: `BivariateCopula.PDF`, `CDF`, `ConditionalCDF` and `InverseConditionalCDF` over paired
  `IList<double>` lists, each value bitwise the scalar member (the conditional simulation of many
  events in one call). Tested by `Test_CopulaListOverloads` (every shipped family, bitwise against the
  scalar members and against the second coordinate of `InverseCDF`; the Normal copula's closed form by
  SciPy; null and mismatched lists).
- API: `Statistics.ColumnPercentiles(double[,], IList<double>, PlottingPostionType[, out int[]])`: the
  plotting-position percentiles of every column over its finite entries in one call, bitwise
  `Statistics.Percentile(IList, IList, PlottingPostionType)` per column (for example the Weibull
  quantiles of the annual maxima of every cell of a grid: 500 cells, 25-75 ms one call per cell from
  Python, 0.7-1.4 ms). The Type 7 and plotting-position column members share one private column loop.
  Tested by `Test_ColumnPlottingPositionPercentiles` (NumPy `quantile` weibull, hazen and
  interpolated_inverted_cdf values; bitwise per column for every formula; repeated parallel calls
  bitwise; empty shapes; argument errors).
- Performance: `Statistics.Percentile` (Type 7 and plotting-position, scalar and list) sorts the copy
  with `Array.Sort` instead of the stable LINQ `OrderBy`, then writes the signed zeros and the NaNs back
  in their original order, which reproduces the stable order bit for bit (they are the only values that
  compare equal with different bits). Tested by `Test_PercentileSortOrder` (thousands of samples rich
  in ties, signed zeros and NaN payloads, bitwise against the stable sort, for every formula; input
  unchanged; NumPy values).
- API: `PlottingPositions.Alpha(PlottingPostionType)`: the single table of the alpha coefficients, read by
  the named formulas (`Weibull` through `Hazen`, positions unchanged bit for bit), the typed overloads and
  the plotting-position percentiles; and `PlottingPositions.Function(IList<double> weights,
  PlottingPostionType)`, the typed sibling of the weighted alpha overload (Kaplan-Meier as the cumulative
  weight share c_i / W). Existing members keep their signatures and results. rmc-numerics
  `statistics.plotting_position_alpha` and a named formula in `weighted_plotting_positions`. Tested by
  `Test_PlottingPositionAlpha` (the coefficients; named and typed formulas bitwise unchanged; unit weights
  bitwise the unweighted positions of every formula; hand Kaplan-Meier values; refusals).
- API: `IFixedParameterEstimation` (extends `IEstimation`, which is unchanged):
  `Estimate(IList<double> sample, ParameterEstimationMethod method, IList<double> fixedParameters)`, a fit
  with some parameters held at known values (NaN marks a parameter to estimate). `GeneralizedPareto`
  implements it: no parameter fixed is `Estimate(sample, method)` bit for bit, and a fixed location with
  maximum likelihood sets the parameters of `MLE(sample, location)` (both run one shared known-location
  fit; the existing member keeps its signature and values); other combinations raise
  `NotSupportedException`. rmc-numerics `estimate(sample, method, fixed_parameters=...)`. Tested by
  `Test_FixedParameterEstimation` (bitwise against `MLE(sample, location)` at three locations and against
  `Estimate(sample, method)` for every method; the SciPy reference maximum; refusals).
- API: `Statistics.ColumnMeans(double[,][, out int[]])`: the mean of every column over its finite entries in
  one call, bitwise `Statistics.Mean` (sequential sum) per column, excluding NaN and infinite entries as
  `ColumnPercentiles` does; the column members share one private parallel column loop. rmc-numerics
  `statistics.column_means`. Tested by `Test_ColumnMeans` (NumPy `nanmean` values; bitwise per column on a
  1000 x 77 ensemble with NaN and infinities; repeat runs bitwise; empty shapes; null).
- Accuracy: `Tools.Log1p` applies its compensated form log(y) - ((y - 1) - x)/y at every finite x > -1.
  The direct log(1 + x) it used for |x| > 1e-4 lost up to about 1e-12 relative accuracy (8,000 units in
  the last place) for 1e-4 < |x| < 1e-2; the compensated form agrees with the C library's log1p to the last
  bit over 301,000 arguments on Windows. Values for |x| <= 1e-4 and the special values (-1, below -1,
  infinities, NaN) are unchanged; values above 1e-4 move by up to about 1e-12 relative (to the correctly
  rounded result), and so do the members built on it. Tested by `Test_Log1pAccuracy` (Python `math.log1p`
  values to one unit; the small-argument branch bitwise unchanged over 20,000 arguments; special values) and
  the rmc-numerics oracle test against `math.log1p` (64,000 arguments, at most one unit).
- Python: the `rmc-numerics` wheel (`python/rmc-numerics`): `Numerics.dll` from the published
  NuGet package byte for byte (SHA-256 checked), the single CoreCLR loader with `add_assembly`
  for dependent assemblies, bit-exact NumPy/.NET marshaling (`Double`, `Int32`, `Int64`, `SByte`,
  `Boolean` and `Single` arrays and `double[,]`), the loaded-assembly identity, and
  typed wrappers (distributions incl. survival `Empirical`, multivariate normal, `Dirichlet`
  with `GenerateRandomValues` draws bitwise those of the .NET call, copulas, paired

  `BrentSearch`, special functions, matrix helpers, `UncertaintyAnalysisResults`,
  `BootstrapAnalysis`, `parameter_set_quantile_table` over `ParameterSetQuantiles`); scalar and
  array members bind their `double` and `IList<double>` overloads once instead of resolving the
  method group on every call. CI builds
  and tests the wheel on Linux and Windows with CPython 3.12 and 3.14.
- Tests: `Test_EmpiricalDistribution` (survival and strictness Clone/XML round trips, the
```

## GitHub release message

Title: `Numerics v2.3.0`

````markdown
RMC.Numerics v2.3.0 is a focused maintenance release: one correctness fix for empirical
distributions, one new batched quantile member for parameter ensembles, and the first release of
the `rmc-numerics` Python wheel built from the same `Numerics.dll`.

## Highlights

- `EmpiricalDistribution` survival and tied-probability tables now survive `Clone` and XML.
- `ParameterSetQuantiles` evaluates quantiles over a whole parameter ensemble in one call.
- `rmc-numerics`: RMC.Numerics for Python, one wheel for Linux and Windows.

## Reliability and Fixes

- **EmpiricalDistribution Clone and XML.** `Clone` rebuilt the table through the two-argument
  constructor, so a table with descending (survival) probabilities, or with tied probabilities,
  became an ascending, strictly increasing table and failed validation. `Clone` now copies the
  sort orders, the strictness of both axes and the smart-search setting, and `ToXElement` /
  `FromXElement` carry the strictness. Documents written by earlier versions read unchanged, and a
  distribution with the default settings writes exactly the same XML as before.

## Distributions API

- `UnivariateDistributionBase.ParameterSetQuantiles(double[,], IList<double>, out bool[])`: the
  inverse CDF at a list of probabilities under each row of a parameter matrix of the
  distribution's family, with one validity flag per row. Each row is evaluated on a private clone,
  so settings that are not parameters (for example the log base of log-Pearson Type III) carry
  over and the calling instance is never modified. The values are bitwise those of the loop
  `ValidateParameters` → `SetParameters` → `InverseCDF`; invalid rows are `NaN`.
- `UncertaintyAnalysisResults.ProcessMeanCurve(sampledDistributions, probabilities, weights, ...)`:
  the weighted mean curve (the quantile function of the weighted mixture of the sampled CDFs), for
  logic trees and other weighted ensembles. Equal weights reproduce the unweighted mean curve bit
  for bit.
- `Statistics.ColumnPercentiles(double[,], IList<double>[, out int[]])`: ensemble percentiles per
  column (for example per curve node) over the finite members in one call, bitwise
  `Statistics.Percentile` per column, with the count of excluded non-finite members.
- `GeneralizedPareto.MLE(IList<double> sample, double location)`: the maximum-likelihood scale and
  shape at a known location (threshold).
- `ParameterSetQuantiles` is virtual; the `GeneralizedExtremeValue` override evaluates a parameter
  ensemble about three times faster with bitwise the same values.
- `PlottingPositions.Function(IList<double> weights, double alpha)`: weighted plotting positions;
  unit weights reproduce `Function(int, double)` bit for bit.
- `Statistics.WilsonScoreInterval(successes, trials, confidenceLevel)`: the Wilson score interval
  for a binomial proportion.
- `Statistics.Percentile(data, k, PlottingPostionType, dataIsSorted)`: sample quantiles at
  plotting positions (Weibull = Hyndman-Fan type 6, Hazen = type 5, Kaplan-Meier = type 4).
- `EmpiricalDistribution.StrictXValues` and `StrictProbabilities` (read-only).
- List forms of `CCDF`, `LogPDF`, `LogCDF` and `LogCCDF` on every univariate distribution, of
  `Tools.Expm1` and `Tools.Log1p`, and of the bivariate copula `PDF`, `CDF`, `ConditionalCDF` and
  `InverseConditionalCDF`; each value is bitwise the scalar member.
- `Statistics.ColumnPercentiles(double[,], IList<double>, PlottingPostionType)`: plotting-position
  percentiles of every column in one call.
- `Statistics.Percentile` sorts several times faster with bitwise the same results.
- `PlottingPositions.Alpha(PlottingPostionType)` and `PlottingPositions.Function(IList<double> weights,
  PlottingPostionType)`: the alpha coefficient of a named formula, and named weighted plotting positions.
- `IFixedParameterEstimation.Estimate(sample, method, fixedParameters)`: estimation with known parameters,
  implemented by `GeneralizedPareto` (known location by maximum likelihood).
- `Statistics.ColumnMeans(double[,])`: per-column means over the finite members in one call.
- `Tools.Log1p` is accurate to the last unit at every argument (it lost up to about 1e-12 relative accuracy
  for 1e-4 < |x| < 1e-2).

## Python

- `rmc-numerics` 2.3.0 ships `Numerics.dll` from this NuGet release byte for byte (its SHA-256 is
  pinned in the package), with the CoreCLR loader that lets dependent packages add their own
  assemblies to the same runtime, bit-exact NumPy marshaling (including `Int64`, `SByte` and
  `Boolean` arrays), the loaded-assembly identity, and
  typed wrappers, including `statistics.autocorrelation` (`Autocorrelation.Function`),
  `multivariate.Dirichlet` (moments, density and `GenerateRandomValues`) and
  `parameter_set_quantile_table` (`ParameterSetQuantiles`). Requires CPython 3.10 to 3.14 and
  the .NET 10 runtime.
- Speed: enum names are resolved once per process; the overloads of `Statistics.Percentile`, `Mean`,
  `Variance` and `StandardDeviation`, of `OrderedPairedData.GetYFromX`/`GetXFromY`, of `Tools.Expm1`/`Log1p`
  and of `Beta.Incomplete` are bound once; `ccdf`, `log_pdf`, `log_cdf`, `log_ccdf`, `expm1`, `log1p` and
  the copula members cross once per array through the new list forms (element by element on an older
  assembly); `parameter_set_validity` reads the validity flags of one `ParameterSetQuantiles` call;
  `column_percentiles(..., kind=...)` gives the plotting-position column form. Every value is unchanged.
  The packaged runtime configuration compiles methods with loops optimized at first use and turns off
  profile-guided tiering, which makes array calls up to about three times faster in a busy process; the
  `DOTNET_TC_QuickJitForLoops` and `DOTNET_TieredPGO` environment variables override it.

## Upgrade considerations

- Code that cloned a survival or tied-probability `EmpiricalDistribution` previously received an
  invalid copy (its `CDF` and `InverseCDF` threw); it now receives a valid copy with the original
  orientation. `Tools.Log1p` is now accurate to the last unit for 1e-4 < |x|: values there, and the
  values of members built on it, move by up to about 1e-12 relative. No other numerical result changes.
````
